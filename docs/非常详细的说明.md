# 一、项目简介

本项目名称：

```text
dy-live-server
```

主要用于给 DYYY 提供抖音媒体解析能力，重点解决普通抖音解析接口无法稳定获取以下内容的问题：

```text
Live Photo / 实况图片
多张实况图片
实况图片 + 普通图片混合图集
```

当前服务器通过以下组件实现解析：

```text
Node.js
Express
Playwright
Chromium
Sharp
systemd
Tailscale Serve
```

其中 `Playwright + Chromium` 用于直接打开抖音网页并获取真实图片与实况视频资源。

# 十九、Surge Tailscale 配置

当前 iPhone 不使用独立 Tailscale App，Tailscale 通过 Surge 内置功能运行。

当前配置：

```ini
[Proxy]
iOS Tailnet = tailscale, section-name=14pm-tailnet

[Tailscale 14pm-tailnet]
interactive-login = true
hostname = surge-14pm
idle-keepalive = -1
auto-add-magic-dns-rule = true
```

---

# 二十、auto-add-magic-dns-rule

当前配置：

```ini
auto-add-magic-dns-rule = true
```

用于让 Surge 根据当前 Tailnet 的 MagicDNS 信息自动处理对应的 Tailscale 路由。

为了当前服务访问更稳定，仍建议加入显式规则。

---

# 二十一、Surge MagicDNS 显式规则

推荐：

```ini
DOMAIN-SUFFIX,tailc27773.ts.net,iOS Tailnet
```

当前 `ts.tailc27773.ts.net` 属于 Tailnet 内部 MagicDNS，显式让它走 `iOS Tailnet` 对当前架构更稳定。

---

# 二十二、Ubuntu Tailscale IP 规则

当前 Ubuntu：

```text
100.74.54.32
```

推荐：

```ini
IP-CIDR,100.74.54.32/32,iOS Tailnet,no-resolve
```

如果 Windows 也加入同一个 Tailnet：

```ini
IP-CIDR,<Windows-Tailscale-IP>/32,iOS Tailnet,no-resolve
```

---

# 二十三、100.64.0.0/10 规则

Tailscale 使用 CGNAT 范围：

```text
100.64.0.0/10
```

如果已经给实际需要访问的设备配置精确 `/32` 规则，例如：

```ini
IP-CIDR,100.74.54.32/32,iOS Tailnet,no-resolve
```

那么剩余 `100.64.0.0/10` 可以根据自己的 Surge 配置决定是否 DIRECT。

例如：

```ini
IP-CIDR,100.74.54.32/32,iOS Tailnet,no-resolve
IP-CIDR,100.64.0.0/10,DIRECT,no-resolve
```

必须注意：`/32` 精确规则一定要放在 `/10` 大范围规则前面，因为 Surge 从上往下匹配。

# 五十二、故障排查顺序

如果 DYYY 突然不能使用，建议按以下顺序检查。

## 1. systemd

```bash
systemctl is-active dy-live-server
```

应该：

```text
active
```

如果不是：

```bash
sudo systemctl restart dy-live-server
```

## 2. 本机 health

```bash
curl -s http://127.0.0.1:8899/health
```

如果这里失败，重点检查：

```text
Node
server.mjs
Chromium
依赖
systemd
```

## 3. Tailscale Serve

```bash
tailscale serve status
```

正常：

```text
https://ts.tailc27773.ts.net (tailnet only)
|-- / proxy http://127.0.0.1:8899
```

## 4. Ubuntu HTTPS

```bash
curl --noproxy '*' -s https://ts.tailc27773.ts.net/health
```

如果本机 127.0.0.1 正常，但这里失败，重点检查：

```text
tailscaled
Tailscale 登录状态
Tailscale Serve
MagicDNS
```

## 5. iPhone Safari

打开：

```text
https://ts.tailc27773.ts.net/health
```

如果 Ubuntu 可以打开而 iPhone 不行，重点检查：

```text
Surge
iOS Tailnet
MagicDNS 分流
Tailnet 登录状态
```

推荐：

```ini
DOMAIN-SUFFIX,tailc27773.ts.net,iOS Tailnet
```

## 6. DYYY

只有 Safari health 正常后，再测试：

```text
https://ts.tailc27773.ts.net/api/dyyy?url=
```

如果 Safari health 正常，但 DYYY 保存失败，运行：

```bash
journalctl -u dy-live-server -f
```

然后重新触发一次 DYYY 保存，观察服务器实时日志。
